# Native Android migration parity audit

Audit date: 2026-09-02. This is a strict audit of the current tree and recorded connected-test evidence against the Flutter screens/drawers, handwritten Rust API, frozen contracts, and the original implementation plan. `Complete` means the production path is wired and has deterministic coverage; target-specific certification limits are stated explicitly.

## Summary

The native lane now implements most wallet behavior, including typed Navigation Compose routing, callback-based JNI requests, lifecycle-owned ordinary operations, balance/connection/payment/recovery streams, validated BIP21/LNURL and other inputs, exact BTC/fiat conversion, animated ecash QR, configurable fail-closed biometric gates, guarded leave, ownership-safe clipboard expiry, visible capped offline retry, explicit Android-session shutdown, paged activity/details, and non-secret stable-identity reconciliation for irreversible operations. Native Rust builds with `--no-default-features --features android-jni`; FRB is optional and cfg-gated for the retained Flutter lane. The clean Android 14 x86_64 preview lane passes 50/50, focused camera coverage passes 5/5, the packaged JNI ownership regression passes 100 cycles, the bounded offline performance probe passes, the persistence probe passes, isolated nondebuggable R8/JNI passes 4/4, and the exact locked Android graph has a zero-finding OSV scan. Final cutover remains blocked by the signed Flutter upgrade fixture, physical arm64 runtime evidence, live federation/payment streams, full product performance, the failing six-finding RustSec gate, and the hardware security/accessibility matrix.

Status totals: 34 complete, 11 partial, 1 missing.

## Remaining source-actionable blockers

1. Extend connected coverage with recovery recreation using a real stream and process termination during invoice creation, quote review and submitted payment; then run the applicable suite on physical arm64 hardware. The x86_64 suite proves Activity recreation and JVM regressions prove recovery resubscription, transient cancellation and leave reconciliation. The offline force-stop probe proves only persisted synthetic safety metadata across distinct PIDs; it does not substitute for killing the process around a live operation.
2. Add connected observation/cancellation of a real native stream. The packaged-library source now opens two isolated, uninitialized databases through the production async JNI bootstrap, proves repeated-bootstrap identity and shutdown/rebootstrap handle generations, and cleans up without creating entropy or accessing the network. A real `ConduitClient` stream cannot be constructed safely offline: the production client constructor is reached only by joining/loading a federation, join requires a live invite/guardian network, and Rust exposes no deterministic synthetic `ConduitClient` constructor. Using an invalid handle would test only error delivery, while adding a test-only JNI client would not prove the production boundary. Host Rust subscription/session tests therefore remain the strongest deterministic stream evidence until a safe upstream client fixture or connected federation test environment exists.
3. Add a historical-format logical fixture covering federation config and payment-history DTOs without requiring live federation access, if Fedimint exposes a safe deterministic test constructor.

## Compatibility-path findings

- The contradictory synchronous Kotlin I/O/payment contract and legacy direct `sendLightning`/`sendOnchain` bypasses have been removed. Production Kotlin now uses callback-based suspend methods for bootstrap, snapshots, network conversion, management, LNURL preparation and quote/execute payment operations.
- Currency catalog, seed suggestions/validation, BIP21/input parsing, cached sats-to-fiat and fountain codec calls remain intentionally synchronous because they are bounded local operations. They are not evidence of a blocking network compatibility path.
- Several Kotlin tests inject callbacks or JSON-returning local bindings. They validate Kotlin parsing, cancellation and race semantics but do not prove JNI symbol wiring or real Rust behavior. Rust tests cover native behavior; the recorded x86_64 `NativeJniSmokeTest` run proves packaged-library symbol/classifier calls and real production database bootstrap/shutdown/rebootstrap on that target, but cannot safely create a real client stream offline.
- `MainActivityTest.nativePreviewLaunches` remains only a launch/UI assertion. `NativeJniSmokeTest` establishes the x86_64 preview JNI/database boundary, and its isolated non-debuggable R8 execution proves those exercised bindings survive shrinking. Production signing, physical arm64 and live-stream lifecycle evidence remain separate gates.

Until the Critical gates above are closed, retain Flutter as the upgrade/behavior oracle and distribute native builds under the preview identity only.
